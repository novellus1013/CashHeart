# 카피·시각화 톤 규칙 (비협상 — PRFAQ 결정)

CashHeart v2.0의 모든 사용자 노출 텍스트·시각화·아이콘에 적용한다. 앱의 정체성은 "관계의 균형/일방성을 **관찰자 시점**으로 보여주되 판단하지 않는다"는 것이다. 어기면 제품 포지셔닝 자체가 무너진다.

## ❌ 금지

- **비난조·평가 어휘**: "부족", "낮은", "차이남", "균형이 깨졌습니다", "당신이 더 많이 주고 있습니다", "관계 점수".
- **방향성 화살표(↑ ↓ →)**: 우열·판단처럼 읽힌다. 방향성은 텍스트 기호가 아니라 **형태**(게이지 기울기, 막대 비율)와 **부드러운 색**으로만 전달한다.
- **금액 강조 중심 카드**: 카드의 무게는 금액이 아니라 *관계의 시간/순간*에 둔다.

## 색 매핑 (Sprint 2 Phase B 시안 검수에서 확정, 2026-07-10)

- **준 마음(given)=파랑 계열, 받은 마음(received)=빨강 계열.** 코드에서는 `Theme.of(context).extension<AppColors>()!.given`/`.received`로만 참조한다(`primary`/`secondary` 직접 사용 금지 — 자세한 내용은 `.claude/rules/design-tokens.md`).
- `design_handoff_cashheart/README.md` 원문은 반대(primary=given=빨강)로 적혀 있으나, 실제 화면에서 어색하다는 사용자 피드백으로 뒤집었다. **Sprint 3에서 9화면을 이식할 때 문서 원문이 아니라 이 규칙을 따를 것** — 문서와 코드가 다르다고 문서를 신뢰해 되돌리지 말 것.
- 관계 균형 상태(balanced/tilted/severe)는 `given`/`received`와 별개의 색 채널이다. **방향과 무관하게 치우침의 크기만** 반영한다 — 받기만 많이 했다고 다른 색, 주기만 많이 했다고 다른 색을 쓰지 않는다(방향에 가치판단을 얹지 않는다는 이 문서의 원칙과 동일한 이유). `lib/theme/balance_state.dart`의 `BalanceState.fromTilt()` 참고.

## ✅ 권장

- **따뜻한 정(情) 어휘**: "오고 간 정", "주고받은 마음", "5년간 9번의 마음".
- **일방성은 사실로만**: "이 관계는 한쪽으로 흐르고 있어요" / "주고받음이 균형 잡혀 있어요".
- **중립·관찰**: 감정을 자극하지 않고 사실을 제시한 뒤 사용자의 해석 여지를 남긴다.

## 예시

| 나쁨 ❌ | 좋음 ✅ |
|--------|--------|
| "이 친구는 균형이 깨졌습니다" | "이 관계는 한쪽으로 흐르고 있어요" |
| "관계 점수: 5/10" | "5년간 9번의 마음을 나눴어요" |
| "당신이 더 많이 주고 있습니다" | "주고받음이 한쪽으로 기울어 있어요" |
| "받은 정이 부족해요 ↓" | (형태·색으로만 표현, 문구는 중립) |

## 적용 범위 예외 — 유저 자발 공유 카드 (2026-07-11 확정)

위 중립·비판단 원칙은 **앱이 화자인 인앱 시각화/카피**에 적용된다. **유저가 자발적으로 공유(opt-in)하고 직접 편집 가능한 공유 카드**는 유저 자신이 자기 관계를 담백하게 놀리는 자기표현이므로, 무례하지 않은 선(비꼼·비난 배제, 치켜세움·축복 위주)의 유머를 허용한다. 앱이 판단을 내리는 게 아니라 유저가 농담을 고르는 구조라는 점이 예외의 근거다.

- 허용 예: "일방통행 기부천사"(주기만 한 관계를 치켜세움), "영혼의 동반자"(누적 우정을 축복).
- 여전히 금지: 지인을 깎아내리는 어조, 비꼼.
- **금액 노출(2026-07-12 결정으로 완화)**: 원래는 비율%·횟수만 허용하고 실제 금액은 전면 금지였으나, "임팩트 있는 카드"를 위해 실제 금액(준/받은 원화) 표시를 **기본값으로 허용**한다. 단 유저가 공유 화면에서 언제든 끌 수 있는 토글이 함께 제공되어야 한다(`card_share_screen.dart`의 "실제 금액 표시" 스위치) — 강제 노출이 아니라 기본 노출 + opt-out 구조라는 점이 완화의 조건이다.
- 공유 카드 문구는 유저가 인카드에서 직접 편집 가능해야 하며(자율성), 이 예외가 인앱 화면(홈/Report/person_detail 시각화)으로 번지지 않는다.

## 적용 시점

- Sprint 3: 균형 시각화 카피 + 톤 (사용자 검수 게이트)
- Sprint 4: 카드 공유 문구 — 런타임 AI 대신 **정적 JSON 템플릿**(케이스당 ~20개). 템플릿은 AI로 오프라인 대량 생성하되 배포 전 사람이 위 금지/권장 기준으로 톤 큐레이션한다. AI 생성 단계 프롬프트에도 위 금지/권장을 명시적으로 넣는다.
